# Contributing

Work only in this repository. The implementation plan and compatibility
assessment are the authority; sibling platform repositories are read-only.
Do not invent delegation, read/write directly from storage, or forward Verentis
credentials to CODE. Never add a live-enable environment switch.

Use Node 24, npm, .NET 10 and Docker Compose. Run `npm ci`, `npm run check`,
`dotnet test` and the real synthetic browser suite as described in README.
Use the fixtures generated by `npm run fixtures`; don't add customer documents.
Maintain tests for authorization expiry, scope, read-only writes, concurrent
CAS, lock lifecycle, restart and independent parent/child message boundaries.

Dependency/image changes require lock updates, upstream licensing inventory,
actual registry-digest verification and repeated browser round trips. Update
the per-format evidence, not MIME claims. No format claims or live integration
approval follow from a unit test.

PR workflows require no secrets or cloud roles. Release preparation is manual
and unsigned. Publishing, importing, deployment, repository visibility/license
changes and platform adoption require separate owner approval. No automatic
commits are part of the implementation workflow.
